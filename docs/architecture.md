# Architecture

## Overview

Personal portfolio of Ugolin Ollé (freelance full-stack developer) **and** a shadcn-style UI registry, served from one Next.js site (`apps/web`, <https://ugolin-olle.com>). The registry's components are distributed through two channels built from the same sources: the shadcn registry (`/r/<name>.json`) and an npm package (`@whoa-studio/ui`).

Rendering and SEO details live in [seo-audit.md](seo-audit.md). Contributor steps for adding an item are in [`CONTRIBUTING.md`](../CONTRIBUTING.md); the full recipe for components, blocks and templates, with the mandatory design + animate + motion workflow, is [creating-items.md](creating-items.md).

## Stack

- TypeScript 6 on Bun 1.2 (workspaces) + Turborepo
- Next.js 16 (App Router), React 19, Tailwind CSS 4
- Fumadocs (`fumadocs-core` / `-mdx` / `-ui`) for MDX content, page trees and search
- `react-i18next` for the home page UI strings, `?lang=` for translated MDX
- oxlint + oxfmt (lint/format), husky + lint-staged (pre-commit)

## Layout

```
apps/web/                 the site (Next.js)
  content/                MDX: components/ blocks/ templates/ projects/ writings/
  examples/<name>.tsx     demo of each registry item (becomes `<name>-demo`)
  public/r/               generated by `shadcn build` — do not commit edits
  src/app/                routes: (home) projects writings inspirations ui api og (llms) …
  src/components/         core/ mdx/ sections/ docs/ registry/ projects/ writings/ icons/ effects/
  src/lib/                source.ts (Fumadocs loaders), registry.ts, metadata.ts, i18n.tsx
  src/data/               home page content: projects, works, social-links, resources, inspirations
  src/locales/{en,fr}/    common.json — home page UI strings
  source.config.ts        Fumadocs collections + frontmatter schemas
packages/
  <item>/                 one workspace package per registry item (index.tsx + modules)
  shadcn/                 shadcn primitives (`bun run bump-ui` refreshes them)
  ui/                     @whoa-studio/ui: registry.json generator, tsup build, npm package
  templates/              @whoa-studio/templates: CLI (`add`, `list`) + its own registry (registry.json, registry/<template>/)
  config/                 shared tsconfig presets (base, nextjs, react-lib, registry-item)
docs/                     this folder
```

### Hero figure

`src/components/sections/hero-figure.tsx` mounts a vendored Hairline figure (`src/lib/hairline/`: `kernel.js` is the unmodified engine, `pipeline.js` the maquette → code → conteneur → production figure; both are excluded from oxlint/oxfmt so the kernel stays byte-identical). It is 16rem wide on mobile (below the text) and 20rem beside the headline from md, loaded with dynamic `import()` when the browser is idle and the box is in view; the 5:4 box is reserved so nothing shifts. Theme follows the `.dark` class set by next-themes. With `prefers-reduced-motion` it gets `pointer-events-none` and stays at rest. To swap the figure, replace `pipeline.js` (it must export `mount`, `means`, `range`).

Registry item packages today: `activity`, `avatars`, `blog`, `button`, `button-apple`, `button-gandi`, `button-shopify`, `calendar-sync`, `cta-simple`, `headers`, `input`, `landing-saas`, `shortcut`, `status-card`, `usage-card`.

## Key flows

**Registry item → docs page and install channels**

1. `packages/<item>/` declares `"registry": { title, type, category?, examples? }` in its `package.json`.
2. `packages/ui/scripts/registry.ts` (`registry:generate`) walks `packages/*`, validates them (name, description, `index.tsx` entry, declared vs imported npm deps, example files exist) and writes `packages/ui/registry.json`. It also emits a `<name>-demo` item per example from `apps/web/examples/`.
3. `shadcn build` turns `registry.json` into `apps/web/public/r/*.json` (shadcn channel). `tsup` builds `dist/<name>.{js,cjs,d.ts}` (npm channel).
4. A docs page in `apps/web/content/{components,blocks,templates}/` links to the item with `preview: <name>` in its frontmatter; `src/lib/registry.ts` joins page and registry entry (dependencies, examples, install commands).
   Template pages (`/ui/templates`) render edge to edge and their Code tab is a file explorer (`FileTreeCodeBlock`) listing the template's own files plus the demo; the tree and the code scroll independently in a bounded panel.

### Templates CLI (`packages/templates`)

`registry.json` there is hand-written (official schema; `registryDependencies` are explicit) and lists templates whose sources live in `registry/<template>/`. `registry:build` runs `shadcn build` into `apps/web/public/r/` (next to the `packages/ui` items) and copies `registry.json` to `/r/templates.json`, the index read by `templates list`. The CLI (`src/`, built with `bun build --target node`) checks that `${WHOA_REGISTRY_URL}/r/<name>.json` exists, then spawns `shadcn add <url>`; it copies no files itself. Default `WHOA_REGISTRY_URL` is `https://ugolin-olle.com`.

`apps/web` runs `registry:build` before `dev` and `build` (`predev` / `prebuild`).

**Primitive docs pages**

The shadcn primitives (`packages/shadcn/components/ui`) are not registry items, so their pages in `apps/web/content/components/primitives/<name>.mdx` have no `preview` frontmatter. They embed `<PrimitivePreview name="<name>" />`, which imports `apps/web/examples/primitives/<name>.tsx` and shows that file as the code tab. Demos import from `@/components/ui/<name>`. Add a page to the folder's `meta.json` to list it.

**Content → pages**

`source.config.ts` defines five Fumadocs collections; `src/lib/source.ts` turns each into a `loader` (`/ui/components`, `/ui/blocks`, `/ui/templates`, `/projects`, `/writings`). Projects and writings are i18n'd: `<name>.mdx` is French (default), `<name>.en.mdx` is English, served on the same path with `?lang=en` (see `getPageLocales` / `resolvePageLocale`).

**Machine-readable output**

`/llms.txt`, `/llms-full.txt`, `/llms.mdx/{components,blocks,templates}/…` expose registry docs as text; `/api/search` merges the three registry search indexes. See [api-contracts.md](api-contracts.md).

**Motion**

The primitives in `packages/shadcn/components/ui` animate with CSS transitions driven by tokens in `packages/shadcn/styles/globals.css` (`--duration-*`, `--ease-*`, `--motion-offset`, `--motion-pop-scale`, the `can-hover` variant). Base UI overlays use the class recipes in `packages/shadcn/lib/motion/overlay.ts` (`data-starting-style` / `data-ending-style`); Motion (`motion/react`, via `LazyMotion` in `lib/motion/provider.tsx`) is used only for `FieldError`. `lib/motion/tokens.ts` mirrors the CSS tokens in seconds: change both together. `motion` is in the root catalog, a dependency of `@whoa-studio/ui` and listed in `tsup.config.ts`'s `CLIENT_PACKAGES`. Rules and per-component decisions: [ui-animation-plan.md](ui-animation-plan.md) and the Motion page in `apps/web/content/components/core/motion.mdx`.

## Boundaries and rules

- `packages/ui/registry.json` is **generated**; never edit it by hand. Commit the regenerated file (the docs site imports it).
- Registry item sources import shared code only through shadcn aliases (`@/lib/utils`, `@/components/ui/<x>`, `@/components/ui/ugolin/<x>`, `@/components/blocks/<x>`), never relative paths into other packages. Internal modules of one item are imported relatively.
- `apps/web` consumes items through the registry and examples, not by importing `packages/<item>` directly in pages.
- `ui` items are a single `index.tsx`; anything multi-file is a `block`.
- Files using hooks, state, effects or handlers need `'use client';`.
- The home page UI is client-side i18n (server always renders French); MDX translations are per-file. Keep both `locales/en` and `locales/fr` in sync.
